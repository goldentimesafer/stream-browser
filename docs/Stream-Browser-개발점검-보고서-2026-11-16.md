# Stream Browser — 개발 점검 보고서

작성일: 2026-11-16 · 대상: `main` (병합 커밋 `67002d2`, PR #1~#3 포함) · 관점: 시니어 iOS 브라우저 앱 개발자

## 1. 한 줄 결론

**설계와 코드는 개인용 비공개 브라우저로서 수준이 높지만, 현재 상태는 "시뮬레이터에서 실행되는 앱"이지 "검증된 앱"이 아니다.** 명세서가 가장 먼저 하라고 한 실기기 스파이크(W03)를 건너뛴 채 전체 기능을 구현했고, 이 앱의 핵심 가치인 데이터 보호·백그라운드 전송·HLS 오프라인·Face ID는 단 한 번도 실제 iPhone에서 확인되지 않았다. 앱 아이콘, 버전 관리, 다운로드 관리자 자동 테스트도 비어 있다.

종합 등급: **B** (설계 A, 코드 B+, 검증 C, 배포 준비 C)

문서를 먼저 쓰고, 참고 코드의 출처·해시·이식 범위를 기록하고, 검증 계획을 코드보다 먼저 만든 점은 개인 프로젝트에서 보기 드물게 좋은 습관이다. 문제는 그 문서가 정한 관문을 스스로 지키지 않은 것이다. `libswiftWebKit` 때문에 앱이 켜지자마자 종료되던 결함은 스크린샷 워크플로를 만든 뒤에야 발견됐는데, W03을 했다면 첫날 잡혔을 문제다.

## 3. 잘 만든 부분

### 3.1 구조
- 역할 분리가 분명하다. `MediaPolicy`(순수 규칙) → `MediaStore`(파일·목록, 순수 Foundation) → `DownloadCenter`(상태) → 화면. 앞의 두 층은 Xcode 없이 macOS `swiftc`만으로 검사할 수 있게 설계되어 Windows 개발 환경의 한계를 영리하게 피했다.
- 세 가지 다운로드 경로(WebKit 전경, 백그라운드 `URLSession`, `AVAssetDownloadURLSession`)를 하나의 작업 모델(`SystemJob`, `DownloadRow`)로 묶었고, 각 경로의 보안 수준 차이를 숨기지 않고 화면에 표시한다.

### 3.2 보안·프라이버시 (이 앱의 핵심 가치)
- 비영속 `WKWebsiteDataStore`, HTTPS 전용, 팝업·미디어 캡처·AirPlay·PiP 차단, Web Inspector 비활성, 스크립트 브리지 없음.
- 다운로드: 교차 출처 리디렉션 거부, 파일 헤더(`ftyp`/`moov`)와 재생 가능 여부 이중 확인, `MediaStore.resolve`의 경로 탈출 차단, 공개 출처는 쿼리·토큰 없는 주소만 허용, HLS 목록을 다운로드 전에 직접 파싱해 라이브·암호화·외부 호스트를 거부.
- 저장: 영상·목록에 `.complete` 보호, iCloud 백업 제외, 전체 URL을 영속 영역에 남기지 않음, 오류 문구에 URL 미포함, 로그 호출 0건.
- 화면: 앱 전환 스냅샷 가림(`WindowPrivacyCover`), 백그라운드 진입 시 잠금과 화면 리셋.
- 어제 보강한 유니버설 링크 차단·길게 누르기 메뉴 정리·Release 빌드 잠금 고정까지 포함하면, 같은 규모의 개인 프로젝트 중 상위권이다.

### 3.3 복구 설계
- 작업 저널(`jobs.json`) + 보류 가져오기 기록(`Imports/*.json`) + 목록 백업의 3중 구조로 "이동 전/후/목록 저장 후 강제 종료"를 모두 다룬다. 9개 시나리오가 실제 임시 디렉터리로 검사된다.
- 취소 기록과 실제 시스템 작업을 대조해 잔여 파일을 정리하고, 전체 삭제는 취소 완료를 기다린다.

### 3.4 공정
- 참고 소스(Brave)의 커밋·blob SHA·이식 판정을 `manifest.json`에 남겼다.
- CI가 경고를 오류로 취급하고(`SWIFT_TREAT_WARNINGS_AS_ERRORS`), 금지 라이브러리 링크를 빌드 단계에서 잡는다.
- 아이콘 버튼마다 `accessibilityLabel`이 있고 터치 영역 44pt를 지켰다.

## 4. 빠진 것과 고칠 것

우선순위: **P0** 실사용 전 필수 · **P1** 첫 개인 사용판 전 권장 · **P2** 이후 개선

### P0 — 실기기 검증 (가장 큰 구멍)
다음은 시뮬레이터로 확인할 수 없고, 코드가 맞아 보여도 iOS 실제 동작이 다를 수 있는 항목이다. 현재 **전부 미확인**이다.

| 항목 | 왜 실기기여야 하는가 | 관련 코드 |
|---|---|---|
| 잠금 중 백그라운드 전송 완료 | `.completeUntilFirstUserAuthentication` 폴더에 시스템이 파일을 넣을 수 있는지, 최종 `.complete` 전환이 성공하는지 | `MediaStore.takeBackgroundFile`, `finalFile` |
| 앱 종료 후 시스템 세션 재연결 | `handleEventsForBackgroundURLSession` 호출과 `allTasks` 복원 | `connectSessions`, `acceptSystemEvents` |
| HLS 오프라인 재생·패키지 보호 | `.movpkg` 위치가 앱 컨테이너 밖일 수 있고, 하위 파일에 보호 속성을 걸 수 있는지 | `assetReference`, `protectAsset` |
| 화질·언어 선택 | `AVAssetVariantQualifier`, `mediaSelections`의 실제 효과 | `HLSDownloadOptions.configuration` |
| Face ID / 기기 암호 | `LAContext` 실패·취소·lockout 흐름 | `BrowserRoot.authenticate` |
| 사진 앱 저장, 파일 앱 내보내기 | 권한 대화상자와 공유 시트 | `LibraryScreen` |
| 어제 추가한 기능 | 당겨서 새로고침, 데스크톱 모드, 길게 누르기 메뉴(비공개 식별자 필터), 알림 | `PrivateBrowser`, `DownloadNotifier` |
| 유니버설 링크 차단 | `allow + 2` 정책 값은 공개 API가 아님. 동작하지 않으면 조용히 실패 | `WKNavigationActionPolicy.allowWithoutAppLinks` |

권장: 검증계획 §6의 B01~B03, H01~H05와 수정검증 v1.3의 "iPhone 인수 확인" 표를 그대로 실행하고 결과를 `docs/`에 기록한다. 이것이 끝나기 전에는 기능을 더 추가하지 않는 것이 좋다.

### P1 — 앱 완성도
> 2026-11-16 조치: 1·2번과 P2-1(상태 열거형)은 PR #4에서 처리했다. 3~6번은 남아 있다.

1. **앱 아이콘이 없다.** `Assets.xcassets` 자체가 없어 홈 화면에 빈 격자 아이콘으로 표시된다(스크린샷 `startup.png`에서 확인). `AppIcon`과 `AccentColor`를 담은 에셋 카탈로그를 추가하고 프로젝트에 리소스로 등록해야 한다.
2. **버전이 한 번도 올라가지 않았다.** PR 3개를 병합했지만 `MARKETING_VERSION 0.1.0`, `CURRENT_PROJECT_VERSION 1` 그대로다. 기기에서 어떤 빌드가 설치됐는지 구분할 수 없고, 일부 사이드로드 도구는 같은 버전을 갱신으로 보지 않는다. CI에서 `CURRENT_PROJECT_VERSION=$GITHUB_RUN_NUMBER`를 주입하고, 기능 변경 시 `MARKETING_VERSION`을 올린다.
3. **다운로드 관리자에 자동 테스트가 없다.** 804줄의 `DownloadCenter`가 큐·동시 2개 제한·취소·일시정지·복원·웹 저장 확인을 모두 다루지만 검사 코드가 0줄이다. 정책·저장소 검사가 잘 되어 있는 것과 대비된다. 상태 전이를 분리해 macOS 검사에 넣을 수 있다(아래 P2-1과 함께).
4. **갱신 시 데이터 유지 확인.** 개인 설치는 7일마다 재서명·재설치할 수 있다. 같은 Bundle ID·같은 서명 팀이면 컨테이너가 유지되지만, 도구나 계정이 바뀌면 저장한 영상이 사라진다. 보완기능 §5의 4단계("갱신 데이터 유지")가 아직 수행되지 않았다. 최소한 "내보내기 후 재설치" 절차를 문서에 넣어야 한다.
5. **메모리 경고 처리가 없다.** 명세서 §12는 메모리 경고 처리를 요구하지만, 탭 20개의 `WKWebView`를 모두 유지하면서 `didReceiveMemoryWarning`에 반응하는 코드가 없다. 비활성 탭의 웹 콘텐츠 프로세스가 종료되면 `webViewWebContentProcessDidTerminate`에서 안내만 한다. 구형 iPhone에서는 앱 자체가 종료될 수 있다.
6. **진단 수단이 없다.** 로그를 남기지 않는 설계는 옳지만, 실기기에서 백그라운드 전송이 실패하면 원인을 알 방법이 없다. 명세서 §14가 말한 "익명화된 오류 코드" 수준의 로컬 진단(최근 N건의 `MediaError` 코드와 시각만, 설정에서 보기·지우기)을 넣는 것이 좋다.

### P2 — 코드 품질
1. **문자열 상태.** `DownloadRow.state`가 `"대기 중"`, `"응답 대기"` 같은 한국어 문자열이고 `row.state == "대기 중"`으로 분기한다. 오타 하나가 큐를 멈추고, 지역화도 불가능하다. `enum DownloadState`로 바꾸고 표시 문구는 화면에서 변환한다.
2. **싱글턴 결합.** `PrivateBrowser`가 `DownloadCenter.shared`를 직접 호출한다(알림·다운로드 수락·세션 종료). 테스트에서 대체할 수 없고 두 객체의 수명이 묶인다. 생성자 주입으로 바꾼다.
3. **Swift 6 준비.** 빌드 로그에 동시성 경고 2건이 있다. `SystemTransfers.swift:6`(델리게이트 클로저 `Sendable` 불일치), `DownloadCenter.swift:290`(`AVAssetDownloadConfiguration` 비-`Sendable` 전달). Swift 5 모드라 오류는 아니지만 `SWIFT_VERSION`을 올리는 순간 막힌다. `SystemTransferDelegate`의 `MainActor.assumeIsolated`는 `delegateQueue: .main`에 의존하므로 그 전제를 주석으로 남겨야 한다.
4. **비공개 WebKit 동작 의존.** 유니버설 링크 차단 값(`allow + 2`)과 길게 누르기 메뉴의 식별자 문자열(`WKElementActionType…`)은 문서화되지 않은 내부 규약이다. iOS 업데이트 후 깨져도 컴파일은 통과한다. 실기기 확인 항목에 넣고, 깨질 경우의 대안(메뉴 전체를 직접 구성)을 적어 둔다.
5. **손으로 쓴 `project.pbxproj`.** 객체 ID가 `0000…0031`처럼 연번이다. 동작은 하지만 Xcode에서 열어 저장하면 전부 재작성되고, 에셋 카탈로그·테스트 타깃을 추가할 때 손편집이 늘어난다. 한 번 Xcode(또는 XcodeGen/Tuist)로 정규화하는 것이 안전하다.
6. **도구 체인 불일치.** 기기용 빌드는 Xcode 26.6(iOS 26.5 SDK), 시뮬레이터 검증은 Xcode 16.4(iOS 18.5)다. 설치되는 바이너리와 화면을 확인한 바이너리가 다른 SDK로 만들어진다. 하나로 맞추거나, 둘 다 쓰는 이유를 워크플로에 적는다.
7. **지역화.** 모든 문구가 한국어 하드코딩이다. 개인용이면 문제없지만 `knownRegions`에 `en`이 있어 의도가 불분명하다.
8. **전경 저장의 거친 중단.** 비공개 전경 저장 중 앱을 벗어나면 `stopPrivateTransfers()`가 즉시 취소한다. 설계상 의도된 것이지만 사용자는 "왜 사라졌는지" 알 수 없다. 취소 시 행에 사유를 남기거나, 저장 시작 시 한 번 안내한다.

### 저장소 구성
- 실제 Git 저장소가 `build/publish-96f677a6/`(`.gitignore`로 제외되는 폴더 안)에 있고, 최상위 폴더는 커밋이 없는 복사본이다. 두 사본이 줄바꿈만 다른 채 공존해 혼동과 누락 위험이 있다. 최상위 폴더를 저장소로 만들고(`git init` + 원격 연결) 안쪽 복제본을 없애는 것이 맞다.
- `.claude/data/healthcare/…` 같은 무관한 플러그인 데이터가 프로젝트 폴더에 있다. `.gitignore`에 `.claude/`를 넣는다.
- `reference/brave-media/`는 MPL-2.0 코드다. 개인 사용·비배포면 의무가 없지만, 앱을 남에게 주거나 공개하면 이식한 파일의 라이선스 고지가 필요하다. `NOTICE` 파일 하나로 충분하다.

## 6. 권장 진행 순서

1. **실기기 설치 1회** (W01 종료 기준). 최신 IPA를 재서명해 보유 iPhone에 올리고 iOS 버전·모델을 `docs/`에 기록한다. 아이콘도 이때 함께 넣는다.
2. **W03 스파이크를 지금 수행.** 공개 MP4 1개, HLS VOD 1개로 3개 저장 경로 + 화면 잠금 중 전송 + 강제 종료 후 복구 + 비행기 모드 재생을 확인한다. 여기서 실패하면 기능 추가를 멈추고 고친다.
3. **버전 주입과 `DownloadState` 열거형** 등 P1·P2-1을 한 PR로 처리한다. 규모가 작고 위험이 낮다.
4. **다운로드 관리자 검사** 추가 후 어제 넣은 기능 4종과 보안 보강 5종을 실기기에서 확인한다.
5. 그 다음에 화질 목록·저장 위치 선택 같은 새 기능을 논의한다.

## 7. 총평

이 프로젝트는 "무엇을 만들지"와 "무엇을 약속하지 않을지"를 코드보다 먼저 정했고, 그 약속을 코드에 성실하게 옮겼다. 비공개 브라우저로서의 보안 설계는 상용 앱 기준으로도 설득력이 있다. 반면 "만든 것이 실제로 동작하는가"를 확인하는 단계는 거의 시작하지 않았고, 아이콘·버전 같은 기본 마감도 비어 있다. 지금 필요한 것은 더 많은 기능이 아니라 iPhone 한 대와 하루의 검증이다.
